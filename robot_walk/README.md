# Robot Walk Recognizer — Week 5 implementation

TECH 315 Models of Computation · Group project
Pramish Sihali, Rista Shrestha, Raksha Shrestha, Manish Yadav

One walk written over `{N, S, E, W}` — one symbol is one unit step — is handed
to three independent machines, each answering a harder question and each
needing a strictly more powerful model.

| Tier | Machine | Question | Language | Class |
|------|---------|----------|----------|-------|
| 1 | DFA `M1` | Did the robot ever immediately undo its last move? | no substring in `{NS, SN, EW, WE}` | regular |
| 2 | PDA `P2` + CFG `G2` | Did the robot end on its starting row? | `#N = #S` | context-free, not regular |
| 3 | TM `M3` | Did the robot end exactly back home? | `#N = #S` and `#E = #W` | decidable, not context-free |

## Running it

Python 3.9 or newer, no third-party packages. Run from the repository root.

```bash
python3 main.py NNESSW          # one walk through all three machines
python3 main.py NNESSW --full-tape   # every Turing machine configuration
python3 main.py NNESSW --pause  # stop between machines, one screen at a time
python3 main.py --demo          # the 8 design-validation walks (Week 4, Table 8)
python3 main.py --tables        # print delta1, delta2 and delta3
python3 main.py                 # interactive prompt, used for the live demo
python3 main.py --pause         # interactive prompt, paused: the Week 8 demo setting
```

`--pause` exists for the projector. A full report runs to about ninety lines,
more than a terminal shows at a font size the back row can read, so the report
is handed over one machine at a time: picture, Tier 1, Tier 2, Tier 3, summary.
The text printed is identical either way.

## Files

| File | What it holds |
|------|---------------|
| `main.py` | command-line driver: single walk, demo, tables, interactive mode |
| `robot_walk/spec.py` | the alphabet, the unit steps, the shared `Run` result record |
| `robot_walk/dfa.py` | Tier 1: `DELTA` transition table, `run()`, `state_path()` |
| `robot_walk/pda.py` | Tier 2: `Stack` class, `DELTA` transition table with ε-moves |
| `robot_walk/cfg.py` | Tier 2: grammar `G2` and the leftmost-derivation parser |
| `robot_walk/tm.py` | Tier 3: `Tape` class, `PAIR-CHECK(X, Y)`, generated `DELTA` |
| `robot_walk/grid.py` | the ASCII picture of a walk (presentation only) |
| `robot_walk/pipeline.py` | runs the three machines in order and formats the report |

## Implementation rule we held ourselves to

Each tier is a **real formal machine**, not a Python counter wearing a
machine's name:

- Tier 1 reads its next state out of a dictionary keyed by `(state, symbol)`.
  It never counts.
- Tier 2 owns a `Stack` object that exposes only `push`, `pop`, `top` and
  `is_empty`; the transition table decides which of those to call.
- Tier 3 owns a `Tape` object with a head that moves one cell left or right per
  step, and an 84-entry transition table generated by instantiating one
  `PAIR-CHECK(X, Y)` subroutine twice — as `(N, S)` and as `(E, W)`.

The three tiers share nothing but the input string, and no tier short-circuits
another: all three always answer, because the three questions are independent
rather than nested (`NS` fails Tier 1 but passes Tiers 2 and 3).
